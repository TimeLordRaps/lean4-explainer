| TD-1 | `src/lean4_explainer/scan.py` (declaration names) | A name with a quoted part that contains a space is cut at the space: `def Foo.«bar baz»` is indexed as `Foo.«bar`. Links to it, and the map, then miss it. | Seen on a two-line fixture, 2026-10-10. Quoted names with spaces are rare in the pinned corpora; not counted. | CONFIRMED | The next change to how the scanner reads names. |
| TD-2 | `packages/map` and the core | The map reads a file's imports from the code it is given per declaration, so a project file with no declarations is not followed through: a file that imports only through it does not see what it imports. | The first count ("8 such files with 9 importers") was wrong, far too low: formal-conjectures' `FormalConjecturesUtil.lean`, which only imports, is imported by 1,469 problem files (import census, 2026-10-10). | TD-3 | `packages/map` and `src/lean4_explainer/scan.py` | Imports are parsed twice: the core's `LeanFile.imports` (now used by file pages and passed to extensions) and `deps.imports_in` in the map, which the map uses only when the core gives it no import graph (an older core). The two must keep agreeing. | Both handle the module system's `public`/`meta`/`all` forms and several modules per line, each with its own test. | TD-4 | `packages/corpus-oai` | The map is switched off for openai/math. | TD-5 | `src/lean4_explainer/build.py` (`collect_tree` with `jobs > 1`) | Worker processes do not see `extensions.activate(...)`: on Windows (spawn) each worker indexes with every installed extension, while the main process analyzes with the activated set. | TD-13 | `packages/implications/src/lean4_explainer_implications/pipeline/workspace.py` (`trace_of`) | A module's build trace hashes its source's raw bytes, so a Windows checkout (core.autocrlf, CRLF) and a Linux one (LF) of the same commit get different traces, and so different environment identities and cache keys. The environment id shown on catalogue entries is this identity: a rerun on Linux would name the same environment differently and reuse nothing from the cache. Recorded checks, the rule-set policy and bridge digests are already line-ending free (`content_sha256`). | Found 2026-10-10 with the CRLF digest of the seven-eighths record's inputs. `ComparatorChallenges/DirichletSevenEighths.lean` in this checkout: raw digest ≠ LF digest. | CONFIRMED, small (identity and portability, not correctness) | The next `TRACE_FORMAT` change: hash with `content_sha256`. It invalidates every trace, so every module rebuilds once. |
| TD-14 | `packages/implications/src/lean4_explainer_implications/pipeline/processes.py` (`launch`) | Lean launches take turns only within one Python process. Two pipeline commands run at once (say `discover` and `build`) can both see the same free memory between their launches and together commit more than the reserve allows. | By construction (a `threading.Lock`), 2026-10-10. Seen in the same session within one process: two attempt processes started together and both died, and the machine's other jobs were squeezed. That case is fixed and tested (`test_parallel_launches_do_not_count_the_same_free_memory_twice`). | CONFIRMED (by design); avoided by running one pipeline command at a time | If two stages need to run at once: an OS file lock (`msvcrt.locking` / `fcntl.flock`, released when a process dies) around the turn. |
