# Technical debt

Known problems that are written down instead of fixed, with what was seen and when to look again. Close an entry by fixing it with a test, and say which commit did.

| ID | Where | What | Evidence | Status | Revisit |
|---|---|---|---|---|---|
| TD-1 | `src/lean4_explainer/scan.py` (declaration names) | A name with a quoted part that contains a space is cut at the space: `def Foo.«bar baz»` is indexed as `Foo.«bar`. Links to it, and the map, then miss it. | Seen on a two-line fixture, 2026-10-10. Quoted names with spaces are rare in the pinned corpora; not counted. | CONFIRMED | The next change to how the scanner reads names. |
| TD-2 | `packages/map` and the core | The map reads a file's imports from the code it is given per declaration, so a project file with no declarations is not followed through: a file that imports only through it does not see what it imports. | The first count ("8 such files with 9 importers") was wrong, far too low: formal-conjectures' `FormalConjecturesUtil.lean`, which only imports, is imported by 1,469 problem files (import census, 2026-10-10). Following imports through it took the formal-conjectures map from 6,077 links to 12,707 (4,104 to 7,542 declarations with a link); MIL, PFR, compfiles unchanged, FLT +2. | VERIFIED_RESOLVED 2026-10-10: the core keeps every file's imports (`Objects.modules`) and map 0.2.0 follows them; `test_a_file_sees_through_a_file_that_only_imports`. | — |
| TD-3 | `packages/map` and `src/lean4_explainer/scan.py` | Imports are parsed twice: the core's `LeanFile.imports` (now used by file pages and passed to extensions) and `deps.imports_in` in the map, which the map uses only when the core gives it no import graph (an older core). The two must keep agreeing. | Both handle the module system's `public`/`meta`/`all` forms and several modules per line, each with its own test. Map 0.2.0 needs core 0.3.0, so the fallback is not reached by an installed pair. | ADDRESSED | The next change to the map's cache: drop `imports_in` and the fallback. |
| TD-4 | `packages/corpus-oai` | The map is switched off for openai/math. Its per-page data adds about 10% to a site (measured on FLT: 0.67 MB on 6.8 MB), and that site is already about 900 MB of GitHub Pages' 1 GB. | `map_dependencies = false` in the corpus options; covered by a test. | DEFERRED | If the map data moves out of the pages into files loaded on demand, or the oai pages shrink. |
| TD-5 | `src/lean4_explainer/build.py` (`collect_tree` with `jobs > 1`) | Worker processes do not see `extensions.activate(...)`: on Windows (spawn) each worker indexes with every installed extension, while the main process analyzes with the activated set. The CLI activates everything installed, so it is unaffected; a program or test that activates fewer extensions gets cache entries from the others. | Seen 2026-10-10: a `jobs=4` build that activated four extensions left `lean4_explainer_ecosystem.snapshot.Entry` objects in its cache, which a loader with only those four refused. | CONFIRMED, small | If a build ever needs a subset of the installed extensions; pass the active names in the worker job. |
| TD-7 | `src/lean4_explainer/markdown.py` | Doc comments are drawn as a Markdown subset: tables, indented code blocks, reference-style links and inline HTML show as written. | All doc comments of the seven smaller corpora, 2026-10-10: 15,340 docs, 0 with a table, 2 with a reference-style link, 3 with HTML. | DEFERRED (rare) | If a corpus or a user's project uses them. |
| TD-6 | `packages/reader/src/lean4_explainer_reader/lean2tex.js` (identifiers) | Greek and other Unicode letters inside identifiers (`ϑ`, `η`, `σ`, `𝟙`, `ᵣ`) go to KaTeX as raw characters. KaTeX draws them with fallback metrics and warns, so spacing around them can be off. | Sweep of the seven pinned corpora (144,945 formulas), 2026-10-10: 728 KaTeX warnings, the same before and after the parentheses change; 0 errors. | CONFIRMED (warnings); visual effect SUSPECTED | The next change to how lean2tex writes identifiers: map Greek letters to `\vartheta`, `\eta`, … |
| TD-8 | `packages/corpus-oai/src/lean4_explainer_corpus_oai/implications.toml` (edge `seven-eighths-gives-an-explicit-real-zero-gap`) | The edge is argued in words, not proved in Lean. A bridge theorem (hypotheses → `Real.log 3 / 8 ≤ (1 - β) * Real.log q`, applying `LFunction_ne_zero_of_seven_eighths_lt_re`) would let the kernel check it. | Writing it needs a build of openai/math at fd4aeeb2 on Mathlib d13f23b7 (not built here: about 1.7 GB of Mathlib cache present, the pinned revision not built). Statements and the docs quote were read at the pin, 2026-10-10. | DEFERRED | When an openai/math build is available; then add the bridge in a sidecar Lean file, set `status = "proved"`, and build with the Lean extension. |
| TD-9 | `packages/implications` and `packages/map` | Implication edges are not drawn on the map. They are kept off it on purpose, so the map shows only links read from the code; a separate, clearly marked layer could show them. | Design decision, 2026-10-10: edges are claims with a status, dependencies are facts read from the code, and one picture would blur the two. | DEFERRED | If a corpus has enough edges that a picture helps (more than a handful). |
