Implications

A dependency records which declarations a proof uses: the map and the “uses” lists show those, read from the code. An implication edge records what one result could establish about another, even when the released proof goes another way. It is a claim, so each one keeps its contract: the declarations it starts from and reaches, the exact hypotheses, the conclusion it derives, the commit the statements were read at, and how far it has been checked. The edges are curated beside the project, not written by its authors.

Besides these curated edges, the discovery pipeline checked 100 implications in Lean (14 connections): the catalogue. What it tried and did not establish, and the suggestions still without a Lean check: notes.

The kinds of edge, and what each status means
Strengthens
From the sources and the hypotheses, the conclusion follows, and the conclusion gives the target's statement with more: an explicit constant, a weaker hypothesis, a wider range.
Composes with
The sources together give the conclusion, and it needs each of them.
Specializes to
The target's statement is the source's general statement with particular values or in a narrower setting; the hypotheses say which.
Supports an executable construction
The sources justify a computable definition, the target, and the conclusion says what it computes.
proposed
Proposed: someone suggested it. No argument is recorded, and nothing has checked it.
argued
Argued: the argument is written out below. Lean has not checked it.
proved
Proved in Lean: the bridge declaration states the hypotheses and the conclusion, and proves them.
refuted
Refuted: the evidence below shows it does not hold as stated.
proved, not checked here
The edge file says a bridge proves it, and no Lean check of it ran in this build or was recorded.
kernel-checked
Lean's kernel checked the bridge against the contract with no sorry and no extra axioms: either in this build, or in a recorded check this build compared with the contract, the bridge file, the commit and the corpus files it read. The card says which.
check is stale
A check was recorded, but of another contract, bridge file, commit or corpus file than this build has: it says nothing now.
stale
The edge was read at another commit than the one this site shows: the statements may have changed.

Each source is a hypothesis: the bridge proves this, and the kernel checked that it does.
What it adds to the target
An explicit constant, c = log 3 / 8, where the target says only that some c > 0 exists; and fewer hypotheses: the contract needs none of the target's χ primitive, χ ≠ 1, χ real-valued or 0 < β.
Argument (in words; Lean checked the bridge, not these words)
Suppose 7/8 < β. Take s = β: its real part is β > 7/8, and s ≠ 1 because β < 1, so the pole exception ¬(χ = 1 ∧ s = 1) holds whatever χ is. The source theorem then gives χ.LFunction β ≠ 0, against hzero. So β ≤ 7/8, and 1 − β ≥ 1/8 > 0. Since q ≥ 3, log q ≥ log 3 > 0. Multiplying, (1 − β) · log q ≥ (1/8) · log q ≥ (log 3)/8. This is the target's statement with c = (log 3)/8 ≈ 0.137 > 0, and it uses none of the target's hypotheses that χ is primitive, that χ ≠ 1, that χ is real-valued, or that 0 < β.
